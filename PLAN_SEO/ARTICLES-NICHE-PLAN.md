> Формула Title: `{Отрасль + услуга}: {benefit с цифрами}` (50-70 символов)

---

## Почему канибализма нет

| Статья 1 | Статья 2 | Запрос 1 | Запрос 2 | Канибализм? |
|---|---|---|---|---|
| Бот для салона красоты | Бот для психолога | «бот для салона» | «бот для психолога» | ✅ НЕТ |
| Бот для салона красоты | Бот для записи клиентов | «бот для салона» | «бот для записи» | ✅ НЕТ |
| Бот для ресторана | Бот для кафе | «бот для ресторана» | «бот для кафе» | ⚠️ Возможен |

**Правило:** Если отрасли НЕ пересекаются (салон vs психолог) — канибализма нет. Если отрасли близкие (ресторан vs кафе) — объединяем в одну статью.

## Структура каждой статьи (по 06-CONTENT-GUIDE.md)

| Элемент | Требование |
|---|---|
| Title | 50-70 символов, `{Отрасль}: {benefit}` |
| H1 | Более развёрнутый чем title (НЕ копировать!) |
| MetaDescription | 150-160 символов с CTA «→» |
| Введение | Боль отрасли → как бот решает → пример |
| H2 секций | 8-12: проблемы отрасли, функции бота, этапы, стоимость, ROI, FAQ |
| Таблицы | Минимум 5: цены, функции, этапы, сравнение, кейс |
| Delegation Triggers | 2-3 на статью |
| Ссылки | 2-3 на money page + 2-3 на parent-статью |
| Объём | 2 500-4 000 слов (СЧ/НЧ) |

## Матрица перелинковки (без канибализма)

```
[Нишевая статья "бот для салона"]
    ↓ ссылка на parent
[Parent-статья "бот для записи клиентов"]
    ↓ ссылка на money page
[Money Page /razrabotka-botov]
    → заявка
```

**Каждая нишевая статья ссылается на:**
1. Parent-статью (механизм) — «подробнее о том, как работает запись через бота»
2. Money page — «заказать бота для вашего бизнеса»
3. 2-3 соседние нишевые статьи — «также читайте: бот для ветклиники»
