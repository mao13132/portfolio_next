# ✅ Чеклист статьи — 28 критериев качества

> **Правило "10 из 10":** Перед публикацией задай себе вопрос:
> "Если бы я ничего не продавал, написал бы я эту статью именно так?"
> Если ответ "Нет" — статья слабая.

---

## 🎯 Главный принцип

SEO — это следствие ценности, а не наоборот.

```
Статья → решить проблему лучше всех → люди остаются → делятся → 
ссылаются → Яндекс это видит → растут позиции → растёт трафик
```

> ⚠️ **Важно:** Нам нужны не клики, а КОНВЕРСИИ. Статья должна не просто давать информацию, а приводить к заказу. Каждый блок статьи — это шаг воронки: проблема → решение → кейс → CTA.

## Чеклист: 26 критериев перед публикацией

### Польза (5 критериев)

- [ ] **1. Ответ в первые 30 секунд** — читатель получил ответ на свой вопрос сразу, без воды
- [ ] **2. Не нужно искать ещё 5 статей** — после прочтения все вопросы закрыты
- [ ] **3. Есть реальные примеры** — кейсы из портфолио, конкретные ситуации
- [ ] **4. Есть цифры** — не "быстро", а "4 дня"; не "дорого", а "от 120 000 ₽"
- [ ] **5. Есть ответы на возражения** — "а если дорого?", "а если маленький бизнес?"

### Структура (6 критериев)

- [ ] **6. Один H1** — ровно один заголовок первого уровня
- [ ] **7. Логичные H2/H3** — структура как оглавление книги
- [ ] **8. Есть содержание** — пользователь может перейти к нужному разделу
- [ ] **9. Короткие абзацы** — не больше 3-4 предложений
- [ ] **10. Есть таблицы (минимум 5 на статью)** — цены, сравнения (A vs B), этапы работ, функции, кейсы (до/после). Markdown-формат `| заголовок |`. Минимум 1 таблица на каждые 2 H2-секции.
- [ ] **11. Есть визуалы** — схемы, скриншоты, диаграммы каждые 300-500 слов

### SEO (6 критериев)

- [ ] **12. Один основной запрос** — в Title, H1, первом абзаце
- [ ] **13. Есть естественные синонимы** — 20-100 связанных запросов в тексте
- [ ] **14. Есть FAQ** — 4-6 вопросов с Schema.org разметкой
- [ ] **15. Есть ссылки на коммерческую страницу** — 2-3 ссылки на money page
- [ ] **16. Есть ссылки на связанные статьи** — 3-5 внутренних ссылок
- [ ] **17. Есть блок "Читать дальше"** — ссылки на релевантные материалы
- [ ] **17.1. Нет упоминаний Wordstat в тексте** — в статье НЕТ фраз «по данным Wordstat», «запрос ищут X раз», «частотность», «показов/мес». SEO-метаинформация не видна читателю.

### Доверие (4 критерия)

- [ ] **18. Есть реальные скриншоты** — интерфейсы, код, результаты
- [ ] **19. Есть реальные кейсы** — из портфолио с цифрами и ROI
- [ ] **20. Объяснён выбор подхода** — почему именно так, а не иначе
- [ ] **21. Нет необоснованных обещаний** — только то, что можешь выполнить

### Конверсия (6 критериев)

- [ ] **22. Понятно что делать дальше** — после статьи есть конкретный следующий шаг
- [ ] **23. Есть ненавязчивый CTA** — призыв связаться или посмотреть кейсы
- [ ] **24. Есть ссылки на услуги** — релевантные коммерческие страницы
- [ ] **25. Статья обновляема** — через год можно легко актуализировать
- [ ] **26. Статья ведёт к конверсии** — после прочтения понятно КАК ЗАКАЗАТЬ услугу. Не просто "полезная статья", а статья, которая приводит клиента к действию: написать в Telegram, оставить заявку, перейти на money page. Каждый абзац должен подталкивать к мысли "мне это нужно, хочу заказать".
- [ ] **27. Delegation Triggers (2-3 на статью)** — внутри контента есть conversion блоки, которые мягко подталкивают делегировать задачу. Размещены после секций «Этапы», «Стоимость», перед FAQ. Каждый уникален, ссылается на money page. Пример: «🔧 Не хотите разбираться сами? Доверьте разработку профессионалу».
- [ ] **28. CTA с конкретными цифрами** — ctaTitle и ctaSubtitle содержат конкретные цены, сроки или результат. НЕ общие фразы типа «разберём задачу». Пример: «Хотите лендинг с конверсией 5-12%? Создам за 5-10 дней от 15 000 ₽.»

## Правила написания

### 1. Статья отвечает на ОДИН вопрос

Плохо: `Telegram-боты`
Хорошо: `Сколько стоит разработка Telegram-бота в 2026 году`
Ещё лучше: `Сколько стоит Telegram-бот для интернет-магазина с оплатой и CRM`

### 2. Ответ начинается СРАЗУ

Не так: `Telegram появился в 2013 году...`
Лучше: `Сколько стоит? От 80 до 500 тысяч. Почему такой разброс? Все зависит от функций.`

Человек получил ответ за 15 секунд. Поисковики это любят.

### 3. Статья должна быть лучше ТОП-10

Перед написанием открой 10 конкурентных статей. Выпиши что у них есть. Потом спроси: "Что я могу сделать лучше?"

- У них 5 экранов → у тебя 20
- У них нет калькулятора → у тебя есть
- У них нет примеров → у тебя есть
- У них нет стоимости → у тебя есть

### 4. Один экран = одна мысль

Заголовок → 2 предложения → картинка → таблица → вывод.

Человеку легче читать.

### 5. Максимум конкретики

Не: `Telegram-бот экономит время.`
А: `У нашего клиента оператор отвечал на 300 сообщений в день. После внедрения бота осталось 40.`

### 6. Показывать цифры

Не: `быстро` → А: `4 дня`
Не: `дорого` → А: `от 120 000 ₽`
Не: `большой` → А: `1500 пользователей`

### 7. Иллюстрации каждые 300-500 слов

Не стоковые фотографии. А: схема, диаграмма, скриншот, интерфейс, архитектура, таблица, код.

### 8. Таблицы работают великолепно

| Тип | Цена | Срок |
|-----|------|------|
| простой бот | 80к | 5 дней |
| CRM | 350к | месяц |

### 9. Сравнения — это золото

Telegram Bot VS Telegram WebApp
Python VS Node.js
CRM VS Excel

### 10. Ответить на ВСЕ возражения

"А если дорого?" → отвечаем
"А если маленький бизнес?" → отвечаем
"А если уже есть CRM?" → отвечаем
"А если нужен AI?" → отвечаем

## Психология: что заставляет дочитывать

### Любопытство
В начале обещаешь ответ: "В конце статьи покажу реальную смету Telegram-бота стоимостью 380 тысяч."

### Открытые циклы
"Есть три ошибки." Пока не расскажешь третью — мозг не успокаивается.

### Конкретика
Не "дорого", а "287 тысяч".

### Истории
Не "сделали CRM", а "Ко мне пришла компания. Менеджеры теряли заявки. Через две недели..."

### Контраст
До → После.

### Авторитет
Не "мы лучшие", а "вот код, вот схема, вот архитектура, вот API."

## Формула статьи

1. **Заголовок** = боль или отраслевой запрос
2. **Первый абзац** = ответ на вопрос + цифры
3. **Введение** = почему это важно + что узнаете
4. **Основной текст** = решение + примеры + таблицы + кейсы
5. **Ответы на возражения** = FAQ или отдельный блок
6. **CTA** = что делать дальше
7. **Читать далее** = ссылки на релевантные статьи
