# ⚠️ ПРАВИЛА ВЕРИФИКАЦИИ ДАННЫХ ДЛЯ SEO-СТАТЕЙ

> **ЭТО ГЛАВНОЕ ПРАВИЛО: НИКАКИХ ВЫДУМАННЫХ ДАННЫХ!**
> Все цифры, частотности, статистика в статьях ДОЛЖНЫ быть основаны на реальных данных.
> Если данных нет — НЕ ПИШЕМ статью, пока не проверим через Wordstat.

---

## 1. Что МОЖНО использовать в статьях

### ✅ Разрешённые источники данных:
- **Яндекс Wordstat** — реальные частотности запросов (файл `PLAN_SEO/WORDS/CLEAN_ALL.md`)
- **Реальные кейсы из портфолио** — данные из `PLAN_SEO/bad_works_.py` (ROI, сроки, результаты)
- **Общедоступные факты** — документация API, цены сервисов, характеристики технологий
- **Личный опыт разработчика** — реальные проекты, сроки, проблемы

### ✅ Примеры правильных формулировок:
- «По данным Wordstat, запрос "парсер wildberries" показывается ~500-800 раз в месяц»
- «В моём проекте для селлера WB удалось увеличить продажи на 180%» (ссылка на кейс)
- «API Wildberries позволяет получить данные о товарах через эндпоинт /content/v2/cards»
- «Стоимость разработки парсера начинается от 15 000 ₽» (реальные цены разработчика)

---

## 2. Что НЕЛЬЗЯ использовать в статьях

### ❌ Запрещённые данные:
- **Выдуманные частотности** — «запрос ищут 10 000 раз в месяц» (если это не из Wordstat)
- **Выдуманная статистика** — «90% селлеров используют парсеры» (без источника)
- **Выдуманные кейсы** — «один клиент увеличил продажи на 300%» (если это не реальный проект)
- **Выдуманные цены конкурентов** — «средняя стоимость парсера на рынке 50 000 ₽» (без исследования)
- **Выдуманные сроки** — «разработка занимает 2-3 дня» (если это не реальный опыт)
- **Общие фразы без основы** — «эксперты говорят», «исследования показывают»

### ❌ Примеры НЕПРАВИЛЬНЫХ формулировок:
- «Запрос "парсер Wildberries" ищут 50 000 раз в месяц» ← НЕТ ДАННЫХ
- «85% продавцов маркетплейсов теряют деньги из-за ручного управления» ← ВЫДУМКА
- «Наш клиент увеличил оборот на 500% за неделю» ← НЕТ ТАКОГО КЕЙСА
- «Средняя стоимость парсера на рынке 100 000 ₽» ← НЕ ПРОВЕРЕНО

## 3. Порядок верификации перед написанием статьи

### Шаг 1: Проверить семантическое ядро
1. Открыть `PLAN_SEO/01-SEMANTIC-CORE.md`
2. Найти кластер статьи
3. Проверить: есть ли РЕАЛЬНЫЕ данные Wordstat (✅) или только оценки (❌)
4. Если данных нет — НЕ ПИСАТЬ статью, пока не будет верификация

### Шаг 2: Проверить кейсы
1. Открыть `PLAN_SEO/bad_works_.py` или `PLAN_SEO/WORKS-MAP.md`
2. Найти релевантные кейсы для статьи
3. Проверить что кейсы РЕАЛЬНО существуют в портфолио
4. Использовать ТОЛЬКО реальные кейсы с реальными цифрами

### Шаг 3: Проверить факты
1. Цены — использовать ТОЛЬКО реальные цены разработчика
2. Сроки — использовать ТОЛЬКО реальные сроки из опыта
3. Технологии — использовать документацию, не выдумывать

### Шаг 4: Отметить в статье источники
- Если данные из Wordstat — указать «по данным Wordstat»
- Если данные из кейса — указать ссылку на `/work/{slug}`
- Если данные из опыта — указать «из моего опыта»

## 4. Что делать если данных нет

### Для кластеров БЕЗ верификации Wordstat:
- **Кластер C (Лидогенерация)** — ❌ Нет данных Wordstat
- **Кластер I (API)** — ❌ Нет данных Wordstat  
- **Кластer J (Веб-разработка)** — ❌ Нет данных Wordstat

**Действие:** НЕ писать статьи для этих кластеров, пока не будет проведена верификация через Wordstat.

### Для кластеров с МАЛЫМ количеством данных:
- **Кластер B (Парсинг маркетплейсов)** — ⚠️ Только 3 запроса из Wordstat

**Действие:** Писать статьи ТОЛЬКО по подтверждённым запросам. Не расширять тему на неподтверждённые запросы.

## 6. Ответственность

**Каждая статья должна быть ПОЛЕЗНОЙ и ДОСТОВЕРНОЙ.**

Лучше написать меньше статей, но с реальными данными, чем много статей с выдуманной статистикой.

**Помните:** Яндекс может понизить позиции сайта за недостоверную информацию. Качество важнее количества.
